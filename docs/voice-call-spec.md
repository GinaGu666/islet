# 小岛实时通话 · 方案（修订版）

> 状态：第一步已实现于开发分支，待配置 ElevenLabs 和手机实测。方案由 GPT Astra 和 Fable 5.2 商议得出；文末「实现备注」是 Opus 5.5 的补充。

## 目标

在当前分支点「通话」，用角色自己的模型继续聊。和小岛上同一个角色、在同一段聊天里，自然地从打字切到说话；挂断后文字聊天能接着往下聊。

## 整体结构

- 浏览器沿用现有的 OpenRouter 请求流程，并直连 ElevenLabs 做语音识别和合成。
- VPS 在通话里只负责签发临时令牌。聊天正文、录音和生成稿都不经过 VPS。

## 各环节

| 环节 | 设计 |
| --- | --- |
| 接通 | 浏览器绑定发起通话时的角色和分支。向 VPS 分别领取识别、合成所需的一次性令牌，再直连 ElevenLabs。官方支持 `realtime_scribe` 和 `tts_websocket` 两种令牌，重建连接时重新领取。 |
| 我方发言 | 使用 Scribe v2 Realtime（`scribe_v2_realtime`）显示临时字幕。浏览器可以把多个已转写片段合成一次发言，给句中停顿留出时间；用户也可以点「说完了」立即提交。 |
| 角色回答 | 定稿作为一条普通用户消息进入当前分支，复用原有的人设、历史和记忆。通话短句提示放在 `_tail`，保留现有缓存前缀。角色模型支持思考档位时，本次请求用最低档。首版关闭模型主动发起的工具调用，照常带入聊天原本会带的记忆。 |
| 合成播放 | 浏览器拿到第一个自然短句就送去合成，首选 Flash v2.5，音色按角色配置。ElevenLabs 的 TTS WebSocket 支持 Flash 系列和流式文本输入。 |
| 打断与挂断 | 首版采用「打断」按钮，耳机和外放都可用。角色播放期间暂停向识别端送入麦克风音频；点「打断」后，浏览器先停播、清空队列，再恢复收音。生成请求也由浏览器取消，迟到的音频按轮次标识丢弃。挂断后回到原分支。 |

## 记录以实际播放为准

- 浏览器分别保存当轮生成稿和已播进度。
- 完整播完就提交全文；中途打断就只提交已播完的短句，并标记「被打断」。
- 日记和记忆提炼只读取最终提交的消息。
- 合成失败时，可以重播同一份稿；如果用户选择「查看全文」，就把展示过的全文写入分支。
- 重连按轮次去重。

## 第一版验收

用一段真实聊天测：

1. 先打字聊到一半，接通后问「刚才那句是什么意思？」。
2. 等角色答到第二句时点「打断」，说下一句。
3. 挂断，检查文字聊天能否接续、记录里有没有混进未播内容。

延迟分两段测：「说完到提交」和「提交到实际出声」，方便判断该调断句还是调生成与合成。

范围：保留直接做通话、首版手动打断。

## 实现备注（Opus 5.5）

### 动工前要先定的

1. **ElevenLabs 账号与费用**：需要付费账号。实时识别按时长计费，合成按字数扣额度；聊得多时，这块可能比聊天本身还贵，开工前先看一眼当前的价格表。
2. **音色**：每个角色先在 ElevenLabs 选好声音，记下 voice ID，存进角色设置（只存本机，不进仓库）。
3. **钥匙**：ElevenLabs 的 API Key 只放在 VPS 的 `/etc/islet-server.env`，浏览器只拿一次性令牌。和现有规矩一样，钥匙不进仓库、不进备份。

### 手机（iPhone Safari）上的限制

- 麦克风和出声都必须由一次点击触发：「通话」按钮按下时一并解锁 `AudioContext`。
- 锁屏或切到后台，通话基本会断；首版接受这一点，回到前台提示重新接通。
- 外放时有回声风险：方案里「播放期间暂停送麦克风音频」已经规避了大部分；`getUserMedia` 打开 `echoCancellation`。

### 技术要点

- **录音**：`getUserMedia` → `AudioWorklet` 转成识别端要的 PCM（16 kHz 单声道），分块经 WebSocket 发出。
- **播放**：合成端流式返回音频块，用 `AudioContext` 排队播放；每块带轮次号，打断时清空队列，迟到的块按轮次号丢弃。
- **断句**：生成稿按中文标点（。！？…以及换行）切短句，第一句到手就送合成；太短的句子并进下一句，避免一顿一顿。
- **已播进度**：以短句为单位记录，句子的音频全部播完才算"已播"。打断时只提交这些。
- **通话中的消息**：沿用普通消息结构，额外加 `call: { turn, interrupted }` 之类的标记，界面上显示一个小电话图标；导出、备份格式保持向后兼容。
- **缓存**：通话短句提示进 `_tail`，不动 system，和现在的缓存断点做法一致。

### 建议分步做

1. **第一步**：按住说话（松手提交）→ 角色用声音回答 → 「打断」按钮 → 挂断回到原分支。先把「同一段聊天里从打字切到说话」跑通。
2. **第二步**：Scribe 实时字幕、多片段合并、「说完了」按钮、自动断句调优。
3. **第三步**：延迟测量面板、重连与去重、合成失败重播 / 查看全文。

每一步一个 PR，在手机上实测后再进下一步。
