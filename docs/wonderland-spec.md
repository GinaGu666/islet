# Wonderland · 方案

> 状态：只有方案，还没动工。2026-11-11。
> 方案 C 由 Fable 5.2 提出，GPT Astra 评审；这里是合并两边意见后的版本。
> 有几处要她先拿主意，见「要她定的」。没定之前不要替她定。

## 想要什么

- 小岛是 Saturn 的家。其他角色各有各的地方，比如小和尚住破庙。
- 手机上一张地图，点哪儿进哪儿。
- 码头在考虑中：一个能遇见多位角色的地方。所以技术上一个地点可以住一位，也可以住多位，沿用现有的角色列表就行。
- 以后小岛空了就空着，不挪作他用。

## 路线：一份代码，按地点分仓

- 仍然只有一份聊天代码。页面加载时确定「地点」，这个地点有自己的存储、主题和默认模型。
- 不为每个地点复制一份应用。复制的话，每个修复都要改好几遍，迟早修漏。
- **小岛保持现状：键名不加前缀，IndexedDB 库名不变，一个字节都不搬。** 只有新地点用新的命名。

## 现状（动工前先知道）

- `index.html` 里直接读写 `localStorage` 的地方约 150 处，四十来个不同的键。不是都以 `islet_` 开头，还有 `or_key`、`or_model`、`or_system`、`or_effort`、`or_reasoning`、`or_models`。
- IndexedDB 的库名集中在一处：`IDB_NAME = 'islet'`，只有 `idb()` 里两次 `indexedDB.open`。
- 每个角色最新一块对话在 `localStorage`（`islet_s_<块id>`），由 `loadSessionMsgs` **同步**读取；其余块在 IndexedDB。
- `storageBytes()` / `lsUsedBytes()` 直接枚举全站的 `localStorage`；设置里的容量表按 5 MB 算。
- 启动时有几段旧数据迁移（`or_history`、`islet_mem`、`islet_memblob_*`、`islet_autodistill`、`RETIRED_CC_KEYS`）。这些只属于小岛的历史，新地点不需要跑。

## 设计

### 地点怎么确定

- 第一版用 URL 参数：`?space=temple`。不带参数的原地址仍然直达小岛，她现有的书签和主屏图标不受影响。
- 地点在页面加载时固定。切地点 = 重新导航，不在页面内热切换。
- **只有「不带参数」可以默认进岛。** 参数为空值或不认识的地点：回地图，并且**不写任何数据**。
- 地点用稳定的内部 ID（`island`、`temple`、`dock`……），显示名可以随便改，ID 定了不改。
- 独立路径（`/islet/temple/`）更好看，但 GitHub Pages 上要多部署入口，而且同样不提供存储隔离。先不做。

### 存储怎么分

- **localStorage**：新地点的键加前缀，例如 `w:temple:islet_idx`。小岛沿用原键名。
- **IndexedDB**：按地点分库。小岛继续用 `islet`，新地点用 `wonderland_<spaceId>`。两地即使出现相同的角色 ID、附件 ID 也互不覆盖。不采用「同一个库里给记录加前缀」，那样遍历、清表、按键查询都要逐处处理。
- 各库独立升级，沿用现在 `idb()` 里处理旧标签页阻塞（`onblocked`）的做法。
- **新地点先沿用和小岛一样的冷热分层**（最新一块在 localStorage，其余在 IndexedDB）。
  Astra 建议新地点把正文直接放 IndexedDB，省 localStorage 的份额。这在容量上更好，但小岛读当前块是同步的，新地点改成只走 IndexedDB 就成了两套读写逻辑，「一份代码」的好处被削掉一截。先保持一套；等分仓跑稳了，如果容量确实紧，再把**所有地点**一起改成只走 IndexedDB。

### 配额是全站共用的

换参数、换路径、换库名，都不会多给一份容量。同源的 localStorage 总共约 5 MiB。

- 容量表分两行：「全站合计」和「本地点占用」。
- 提示要说对地方：庙里写满了，不能提示她去归档 Saturn 的对话。
- 「存储写不进去」的常驻提示（`#storage-warn`）同理，要说明是全站的空间满了。

### 防串仓：这是整个方案能不能做的前提

150 处读写里漏改一处，新地点就会读写到小岛的数据。靠人眼检查不够。

- 所有 `localStorage` 访问收进一个统一入口（读、写、删、枚举），由它根据当前地点决定真正的键名。启动时**先**确定地点，再读主题、角色、模型。
- 加一条自动检查（`tools/` 下的测试）：入口之外出现 `localStorage.` 就失败。以后谁加新功能都绕不过去。
- **小岛的键没有前缀，所以不能用 `startsWith('')` 这类判断来认「哪些键属于小岛」**，那会把所有地点的键都算进去。枚举小岛的键时要显式排除带 `w:` 前缀的。
- 四十来个键分三类，入口里写成一张明确的表，不认识的键直接报错：
  - **全站共用**（建议）：`or_key`、`islet_notion_key`、`islet_memsrv_url`、`islet_memsrv_key`、主题 / 字号 / 字体（`islet_theme` `islet_fontsize` `islet_aifont`）、`islet_bear`、模型目录缓存 `or_models`、`islet_quota_nag`。
  - **按地点**（建议）：角色与对话（`islet_companions` `islet_idx` `islet_s_*` `islet_cur` `islet_active_companion`）、打卡 / 名场面 / 活动、`islet_memsync_*` `islet_notes_seen_*` `islet_presence_*` `islet_voice_*`、`islet_last_backup`、聊天相关设置（`or_model` `or_system` `islet_or_routes` `islet_memory_models` `islet_ctx` `islet_tools` `islet_web` `or_effort` `or_reasoning`）。
  - **待她定**：`islet_about` 和 `islet_about_hist`，见下。
- 旧数据迁移那几段只在小岛执行。

### 备份

- 现有的 `islet` 全量备份和 `islet-archive` 归档，**导入逻辑原样保留**。旧的全量备份可能含多位角色，按「历史上的小岛数据」完整恢复，不拆分。
- 新备份写明格式版本、文件类型和 `spaceId`。
- 导入前显示「这份备份来自哪里、要写到哪里」。地点对得上才允许覆盖。
- 备份是按地点导出的。要不要另加一个「全站一起导出」，以后再说。

### 地图

- 一个很小的入口页，列出地点，点了就导航到对应的 `?space=`。
- 放哪儿有两种做法，见「要她定的」第 3 条。
- 地图本身不读写聊天数据。

### 模型线路

`AGENT.md` 写明接口只有 OpenRouter。第一版不改：每个地点只是有自己的默认模型，都走 OpenRouter。破庙用 OpenRouter 上的 DeepSeek 即可，不为它单独接一条线路。

### 记忆库服务器

服务器按角色 ID 分目录，和地点无关。角色 ID 是按时间生成的，两地撞 ID 的可能很小，第一版不处理；如果以后做「按角色复制到新地点」，复制时要换新 ID 或确认不冲突。

## 要她定的

1. **「关于你」是一份还是每地一份？** 所有地点的角色看到同一个她，还是每个地方各写一份。
2. **现在住在小岛上、以后要搬走的角色，历史怎么接？**
   - 开了新库，旧对话不会自己过去。想在新住处接着上次那句话聊，就要按角色复制一次：对话、记忆、日记、附件一起带，核对成功再切入口。
   - 如果不迁移，就要留一个能找到旧历史的入口。
   - 「小岛首页只显示 Saturn」和「小岛的库里只剩 Saturn」是两个独立的决定。前一个可以先做，后一个不急。
   - **破庙不受这条影响**：小和尚现在不在岛上，进庙是新住户，用现有的「导入角色 / 聊天」把记录带进来。
3. **地图放哪儿？** 做成 `index.html` 里的一个界面（保持单文件），或者单独一个小页面 `/islet/map/`（更干净，但仓库里多一个 HTML，和「单文件」的约定不完全一致）。
4. **码头的设定**。技术上已经留了位置，不卡进度。

## 分步

每步一个 PR。**第 0、2 步碰存储和备份，合并前必须有人读过代码**，不能靠先上线再试。

0. **收拢存储入口，行为完全不变。** 只有小岛一个地点、前缀为空。加上自动检查。合并后小岛应该和之前一模一样。这是风险最高的一步，改动面最大，单独做、单独验。
1. **跑通一个空的新地点。** 参数、前缀、分库、容量表两行、未知地点回地图且不写数据。
2. **备份带地点。** 新格式带 `spaceId`；旧备份按原语义恢复到小岛。
3. **地图和各地点的主题。**
4. **搬家。** 把小和尚导入破庙；岛上角色要不要搬，等她定。

## 验收

- **第 0 步后**：用她的一份真实旧备份恢复到一个干净的浏览器，打开冷对话、附件、日记，和改之前逐项对比。
- **第 1 步后**（Astra 提的做法）：给两个地点放入**相同 ID、不同内容**的数据，双开标签页，分别测聊天、归档删除、导出备份、覆盖恢复。每做一步都去另一边核对：数据没变，导出的文件里也没有混进对方的内容。
- 把庙写满，确认提示说的是全站空间，没有叫她去归档小岛。
- 用空的和乱写的 `?space=` 打开：回到地图，`localStorage` 和 IndexedDB 里没有多出任何东西。
- 不带参数打开原地址：直接进小岛，和今天一样。

## 改的时候

照 `AGENT.md`：不引入依赖，不上构建；在 `main` 之外的分支上改；改 `index.html` 就更新版本号；碰存储和备份要保守，先写新的、读回核对，再删旧的；备份格式向后兼容，她手上有旧文件。
